# Nanza 2.9.127 — invoice intake and accounting integrity

This release candidate extends the existing 2.9.126 repository. Existing features and accounting data formats are preserved. GitHub publication and Windows installer status must be checked separately; local acceptance is not a Windows build result.

## Final integration checkpoint

- Commercial documents: quotations, purchase orders and consignment-note formats; draft/confirmed states, separate numbering and optimistic revisions. Confirmed quotations create sales invoices for review. Confirmed orders permit partial receipts and purchase invoice drafts only within received quantities. Operation references prevent duplicate retries. Linked stock/invoices have edit guards.
- Order/receipt/invoice matching shows outstanding quantities and price differences, with explicit Arabic/English PDF/Excel direction. Differences do not automatically revalue inventory. Consignment physical transfers and sales delivery remain separate Stock Documents operations.
- Executive dashboard uses actual posted-ledger figures, side-by-side monthly charts, margin, cash and overdue balances. Budget/prior data remain unavailable when missing. Forecast, gross margin and operating/free cash flow are deliberately unavailable until reviewed mappings exist.
- Literal reader prompt v2 accepts the owner schema, retains supplier tax identity and up to 12 rows, supports explicit French/Arabic number separators and withholds disputed values. Self-reported model confidence/payment status never authorizes posting.
- Interrupted pooled transactions roll back on BaseException. Initialization checks physical integrity before migrations; damaged indexes block upgrades without repair.
- Help includes synthetic invoice/commercial illustrations and a local video picker; no video course is bundled.

## What changed

- Embedded PDF text remains the first reading source. Scanned pages and photographs use existing local readers. Azure is optional and explicitly selected; normal local reading does not send documents to it.
- The original PDF/photo is shown beside editable fields. PDFs have page selection; images retain zoom and rotation. Field origin and supplied reader confidence are displayed. Missing or unavailable confidence is unknown. A derived subtotal is explicitly inferred. Human confirmation is required before using the reading; using it does not approve or post an entry.
- Editable line review preserves missing quantities/prices rather than inventing quantity 1. Header and line arithmetic, item sums and duplicate candidates are checked without altering the transcription to force a balance. Supplier tax identity remains editable. Payment method/status are not inferred.
- Invoice and line classifications are local keyword/account-name suggestions. Only active accounts in the current company chart are eligible; declared account types take precedence over numbering and parent accounts are excluded. Ambiguous matches abstain. Match scores are heuristic, not calibrated probabilities. VAT eligibility requires the accountant's decision; unknown VAT treatment remains unknown.
- Purchases header controls wrap at smaller widths, retaining Arabic layout. The dashboard's Period summary uses posted ledger income/expenses/profit, cash/bank book balances, overdue AR/AP and same-period prior-year comparison. Missing prior-year figures are blank with a warning. PDF/Excel exports use the same snapshot.
- Payment/expense/voucher creation and required approval holds are atomic. Held payments are excluded from posted settlements and reports. Refunds and exchange differences are reflected in ageing. Invoice lists distinguish direct payment from allocated settlement. Account drilldown totals stay separated by currency. The document VAT summary signs credit notes correctly, excludes held/unposted documents and is explicitly provisional; it is not the statutory quarterly return.
- Full Books Health Check checks SQLite physical integrity before accounting calculations. A detected failure stops those checks and asks for preservation/verified restoration; it never repairs the database automatically.

## Limits and next validation

No measured OCR accuracy percentage is claimed. Real anonymized Arabic/English/French printed and handwritten invoices need independently checked ground truth before comparing readers/prompts. No new large vision model was downloaded or benchmarked, and no superiority claim is made for Qwen 2B/3B/4B. The existing evidence-oriented prompt remains useful because it separates literal reading from accounting decisions; the supplied engineering prompt was implemented as product requirements, not passed verbatim as an OCR instruction.

French Tesseract data is added to the Windows build specification. The Windows installer itself has not been built or exercised on the user's i7-6600U computer. This build is not a certification of statutory payroll/VAT filing; README compliance limits still apply. Quotation/consignment formats and partial order workflow are included; end-to-end consignment custody/returns and a recorded help course remain future work.

## Layout review scope and remaining limits

The inspected windows include purchases headers, invoice original/field review, commercial documents and executive dashboard. English/Arabic commercial and executive export paths were exercised. Generic report export now follows the document's explicit language rather than the desktop language. Arabic captions could not be visually certified in the Linux display because of missing glyph rendering; Arabic PDF shaping was visually inspected successfully. This is not a claim that every legacy tab, every printer, every paper size, every report and every lifecycle callback was visually tested. Existing native program-window regression coverage supplements these targeted checks. Windows-only lock behavior and installation on the user's computer need Windows acceptance.

Before accounting use, review actual supplier number, accounts/VAT eligibility, quantities and conversion rates. A quotation conversion creates an accounting draft; delivery/stock issue remains separate. Purchase receipt costing follows the order; price variances require a reviewed adjustment. Optional local neural models were not installed or benchmarked here. No 80% handwriting recognition claim is made.


## Windows installation fixture repair (18 October 2026)

The original GitHub Windows suite and installer run both failed only in `test_setup_marks_ready_only_after_verified_files_and_runtime_check`: the synthetic archive contained `llama-mtmd-cli`, while Windows correctly requires `llama-mtmd-cli.exe`. The fixture now explicitly exercises both platform names. A separate regression verifies that neither platform writes a ready marker or launches a runtime when the archive lacks its executable. Production installation also checks this file before running its existing version probe. Model checksums, runtime probing, enable/disable and incomplete-setup safeguards are retained.

The unreleased version remains 2.9.127. Successful main builds can publish a missing release after a same-version repair; automatic builds preserve assets of existing releases. Manual release uploads retain their existing behavior. Focused reader/release checks: 28 tests passed in 1.595 s. Full repair-source suite: pending result. GitHub Windows validation remains separate from Linux emulation of the platform name.
